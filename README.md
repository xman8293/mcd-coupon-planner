# 薅麦吧（mcd-coupon-planner）

> **最高级的薅羊毛，是抵住自己的底线，知道哪张不该薅。**
> **今天不是我想吃什么，而是券和积分决定我吃什么。**

一个基于麦当劳官方 MCP 的 WorkBuddy Skill：拉取你账户里的优惠券，按过期优先级排成"本周薅单"，每张券都过**官方算价接口**算出真实"净薅额"，并对不划算的券给出"建议放弃"的理由。确认方案后可一键下单（无预下单，确认前零副作用）。

## 为什么做这个

我账户里躺着 **312.4 分已过期积分**——不是没优惠，是没人帮我盯着。

市面上的点餐助手都是"你想吃啥 → 顺便找张券"。薅麦吧因果倒置：**"你有什么券 → 反推这周吃啥"**，并且敢告诉你：哪张不该薅。

那张"仅周六 05:00-10:29 可用"的早餐券，专为它早起不值当——放弃它，也是收益。

## 为什么钱必须过官方算价

本地估算 vs 官方验价的实测对比（2026-10-12，作者真实账户）：

| 券 | 本地估算节省 | 官方算价净薅 | 偏差 |
|---|---|---|---|
| 王牌小食拼 | 4.8 元 | 6.6 元 | 38% |
| 9.9 中杯冰美式 | 3.0 元 | 9.1 元 | **3 倍** |

所以本 Skill 的铁律：**LLM 不碰钱**。所有价格只来自 `calculate-price` 官方接口，大模型只负责理解你的话和把结果说成人话。

## 安装与配置

1. 领取 Token：浏览器打开 [open.mcd.cn/mcp](https://open.mcd.cn/mcp) → 手机号登录 → 控制台激活 API → 复制 Token（免费，600 次/分限流）
2. 设置环境变量：
   - Windows PowerShell：`[Environment]::SetEnvironmentVariable('MCD_MCP_TOKEN','你的Token','User')`
   - macOS/Linux：`export MCD_MCP_TOKEN=你的Token`
3. 把本目录放入你的 WorkBuddy skills 目录，或在对话中直接引用 `SKILL.md`

> Token 只从环境变量读取，本仓库任何文件都不需要、也不应该包含 Token。

## 架构

```
你说人话 → SKILL.md（LLM：理解/澄清/渲染/共情）
              ↓ 唯一入口
        planner.py（六阶段确定性流水线）
              ├─ mcp_client.py     MCP 通信 + Token + 结构化错误
              ├─ coupon_parser.py  券 Markdown → 结构化（星期/时段/渠道约束）
              ├─ classifier.py     五分类：兑换/特价/折扣/买赠/满减
              ├─ optimizer.py      过期排程 + 放弃清单 + 满减凑单 DP（每餐限1券）
              └─ verify.py         券身份 + calculate-price 官方验价 + 净薅额
              ↓
        JSON 契约 → LLM 渲染成卡片（无权改任何数字）
```

设计原则：

- **LLM 不碰钱**：钱在 Python 里闭环，LLM 没有改数字的入口
- **确认前零副作用**：不绑券、不下单；确认后绑券→下单→支付→查单，失败报停在哪一步
- **无预下单**：排程是建议，下单永远基于当下最新券状态重新验价

## 目标用户

- 手里攥着一堆麦当劳券却总忘记用的打工人
- 想把"券快过期"焦虑变成"本周薅单"计划的人
- 想学 MCP 实战的开发者：33 个工具怎么选、Markdown 返回怎么解析、算价怎么闭环，全在代码注释里

## 已知边界

- 门店券接口只返回"当前时段可用"的券：早餐券中午验不了价，属正常（服务端行为）
- 每单限用 1 张券（实测），排程已按此约束
- 满减凑单 DP 已实现（`optimizer.optimize_threshold`），需 `query-meals` 提供菜单价格池
